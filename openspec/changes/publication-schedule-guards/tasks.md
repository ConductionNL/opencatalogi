- [x] 1.3 Add the guard to the `publish` and `publishWithoutReview` transitions as a lifecycle guard (OpenRegister `LifecycleGuardRegistry`) or, if the registry does not accept an app guard, rely on the listener and say so in the PR body (REQ-PSG-001).   - Built as the listener, not a lifecycle guard. OpenRegister's `LifecycleGuardRegistry` does accept an app guard by class name (`ReviewNotRequiredGuard` is one), but a guard's `check(array $object, string $action, string $userId)` sees only the stored object, not the transition's inputs. It cannot tell publish now from a `publish` that keeps the scheduled date, so a guard would also refuse scheduling. `TransitionEngine` merges the inputs into the same save that flips the status, and that save dispatches `ObjectUpdatingEvent`, so `EmbargoGuardListener` meets both transitions and refuses only an earlier date. Tests: `PublicationLifecycleTest::testThePublishTransitionIsRefusedUnderEmbargo` (both transitions with today's date, on the real event) and `::testAPublishThatKeepsTheScheduledDatePasses`.
