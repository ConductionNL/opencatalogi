  - Not built, 24 Nov, because it needs a decision. OpenRegister has the state field rules on both `main` and `development` (`StateFieldRuleResolver`, `LifecycleStateValidator`), and the stored `draft` state is in place, so nothing upstream blocks it. But `BatchPublicationWriter::payload()` writes a Woo batch's publication with only `title`, `wooCategory`, `publicationKind`, `status: approved` and `caseReference`: no `summary`, `description` or `organization`. With D1 as written, every Woo batch publication would be refused at `approved`. Question: (a) the batch writer fills `summary` and `description` from the batch (and from the decision document's text where it has one) and `organization` from the batch's organisation, and the declaration ships with that; (b) require the three only at `published`, and have the batch path publish through a transition that fills them first; (c) leave the batch path out of D1 by giving batch publications their own schema. Recommendation: (a), in the same PR as 1.1, with a `BatchPublicationWriterTest` case that a batch publication passes the declared rule.
  - Built 24 Nov with decision (a). The declaration is `lib/Settings/register.d/publication-required-at-publish.json`; the schema version moved to 0.0.15 in `woo-x-access-boundary-hardening.json`, which sorts last and wins the merge. One deviation from D1: `draft` is left out of `states`, because OpenRegister's `LifecycleStateValidator` refuses an empty `required` list (`lifecycle-state-fields-malformed`); a state without a block has no rule, which is what D1 means. `BatchPublicationWriter::payload()` now writes `summary` (the batch's own, else the title, cut to 255), `description` (the batch's own, else "Besluit en openbaar gemaakte documenten: {title}. Zaak {caseReference}.") and `organization` (the batch's own, else OpenRegister's `@self.organisation` on the batch; none invented, so a refusal names it). Tests: `PublicationRequiredAtPublishSchemaTest` (3, the validator one runs with OpenRegister beside the app), `BatchPublicationWriterTest::testABatchPublicationPassesTheDeclaredRule`, `::testTheBatchsOwnTextAndOrganisationWin`, `::testWithoutAnOrganisationNoneIsInvented`. The clean `occ app:enable` import is not run here (no instance).
  - Held back the same day (#2947 follow-up), so unticked again. OpenRegister's `StateFieldRuleListener` refuses an empty required field on EVERY save, system saves included (no `_rbac` bypass; the updating event is always dispatched). The post-migration repair steps run after `InitializeSettings` imports the schema and re-save legacy published publications: `BackfillPublicationLifecycleState` (status), `SetPublicationAudiencePublic` (audience), `MirrorCaseReferenceIntoSourceIdentifiers`, `MoveDocumentsoortOutOfSummary`. A legacy publication without a summary, description or organisation is refused there, so it keeps no state or no audience and the public read rule hides it. D2's "refused on its next edit" did not account for these steps. The declaration is removed and the publication schema moved to 0.0.16, so an instance that imported 0.0.15 imports the rule away; `BatchPublicationWriter` keeps filling the three fields (harmless, and needed once the rule returns). Before 1.1 ships again, the repair steps must be able to save such a publication: either they write the field as recorded-not-supplied (OpenRegister's `@notSupplied` with a reason the schema administers in `x-openregister-not-supplied-reasons`), or a step that runs before the import fills summary and description from the record itself and the organisation from its catalog. Recommendation: the `@notSupplied` route, since it records the gap honestly instead of inventing text, with 1.4's count reading the same markers. `PublicationRequiredAtPublishSchemaTest` now asserts the rule is absent and the version moved past 0.0.15.
  - Built again 25 Nov with the `@notSupplied` route (decision, b-opencatalogi: the recommendation above; it records the gap instead of inventing text). `lib/Settings/register.d/publication-required-at-publish.json` declares the three states again (draft still left out) and administers one reason, `x-openregister-not-supplied-reasons` `published-before-required`; the publication schema moved to 0.0.18. `RequiredToPublish::recordGaps()` records every required field a record in `in_review`, `approved` or `published` leaves empty as not supplied with that reason (a blank value is cleared, since OpenRegister refuses a marked field that carries one; other entries are kept), and the four repair steps that re-save legacy publications call it right before their save: `BackfillPublicationLifecycleState`, `SetPublicationAudiencePublic`, `MirrorCaseReferenceIntoSourceIdentifiers` and `MoveDocumentsoortOutOfSummary` (which empties a summary). The editor's save drops the entry of a field it now fills (`clearAnsweredGaps()` in `src/services/requiredToPublish.js`, used by `ObjectModal.vue`), since OpenRegister refuses a field that is both filled in and recorded. 1.4's count still counts these publications: a recorded gap is still a gap. Tests: `PublicationRequiredAtPublishSchemaTest` (4, OpenRegister's lifecycle validator included), `RequiredToPublishTest` (3 new), one case each in `BackfillPublicationLifecycleStateTest`, `AudienceMigrationTest`, `MirrorCaseReferenceIntoSourceIdentifiersTest` and `MoveDocumentsoortOutOfSummaryTest`, `requiredToPublish.spec.js` (3 new). The clean `occ app:enable` import is not run here (no instance).
